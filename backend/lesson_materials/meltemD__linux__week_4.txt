Scripting
● In the simplest terms, a shell script is a file containing a series of commands.
● The shell reads this file, and carries out the commands as if they have been 
entered directly on the command line.
● Shell scripts are text files, but it helps if the editor supports syntax 
highlighting. 
● Once you write the code, you have to give execute permissions. 
● The third and final step is letting the shell access the script. 
● Remember that the shell keeps a list of directories in the PATH variable. 
● Or you can supply the path of the script.

Variables
● A variable is a tag / label / identifier / name in the program that refers to a 
corresponding memory location. 
● Variable names start with an alphabetic or underscore character, followed by 
any number of alphabetic, decimal digits, or an underscore character. 
● Variable names are case sensitive. 
● The simplest format for defining a local variable is to initialize it. 
variableName=value
decimalVariable=18
15
Variables
● If the name of the variable is variableName, the reference to its value is 
$variableName, which is the simplified form of ${variableName}.
● There are two type of variables; local and environment
○ Local: private to the shell in which they are created and not passed on to any process 
spawned from that shell. 
○ Environment: variables are passed from parent to child, child to grandchild… 
● If an environment variable is set in the child shell, it is NOT passed back to 
the parent. 
● The env command will display the environment variables.

Arrays
● Arrays allow you to collect a list of words into one variable name. 
● They can be created by declare -a command or on the fly: x[0]=5
$ declare -a myArray                                                            
$ myArray=(first second third fourth)
$ declare -a nums=(34 2 12 2)
$ declare -a array=(ilker [2]=kaya [1]=korkmaz [3]=oguz)
$ echo ${nums[0]} # first element 
$ echo ${#array[0]} # length of first element
$ echo ${#array} # length of first element
$ echo ${#array[*]} # number of elements in array
$ echo ${#array[@]} # number of elements in array                               
$ echo ${array[*]} # all elements in array                                      
$ echo ${array[@]} # all elements in array

Arithmetic with variables
● Variables can be declared as integers with the declare -i command. If you 
attempt to assign any string value, bash assigns 0 to the variable.
● The let built-in evaluates arithmetic expressions. Evaluation only supports 
integer arithmetic. Overflow is not checked. Division by 0 is trapped.
● Instead of let, (( )) can also be used. 
● Since bash only supports integer arithmetic, you can use bc or awk if you 
need floating-point calculations.
● bc is a language that supports arbitrary precision numbers with interactive 
execution of statements.

● Each word following the script name is an argument. 
● Positional parameters are referred as $1, $2, … ,${10}, and so on…

● The $* and $@ differ only when enclosed in double quotes.
● When $* is in double quotes parameter list becomes a single string. 
● When $@ is in double quotes, each of the parameter is quoted.

Flow Control

command1 is successful. 
● With the || operator, command1 is executed, and command2 is executed if 
command1 is not successful.

Functions
● Functions used in user scripts are executed in context of the current shell.
● A child process is NOT spawned as it is when running an executable program. 
● Because the function is executed within the current shell, the variable will be 
known to both the function and the shell.
● Any changes made to your environment in the function will also be available 
to the shell.
● The local variables in a function are private to that function and will 
disappear after the function exits.
● Functions may be stored in another file to be loaded (sourced) into scripts 
when they will be used (see source command).

Handling Spaces
● What about with lists of parameters with blanks? 
● You have to use $@ instead of $*. 
● The parameter $* expands to the list of arguments supplied to the script. 
● That is, if you run your script as 
./my.sh these are arguments
then 
for item in $* 
is expanded as 
for item in these are arguments
65
Handling Spaces
● You might be tempted to try the quotes as 
for item in “$*”
but this expands to 
for item in “these are arguments” 
and you will have a single value… 
● So, the solution is to use $@ with quotes,
for item in “$@”
which expands to
for item in “these” “are” “arguments”

Getting Default Values for Variables
● If you would like to provide default values, you can use the ${:-} syntax 
when referring to the parameter, and use it to supply a default value:
FILEDIR=${1:-/tmp}
● This operator says that if $1 is not set, or is null, then it will use what follows. 
● Otherwise, it will use whatever value is set in $1. 
● It can be used on any shell variable, not just the positional parameters. 
● Notice that $1 is not assigned to /tmp, only a value is returned; either the 
value set in $1, or --if there is nothing set-- /tmp. 
67
Setting Default Values for Variables
● If you also would like to set a default value, if a variable is not set or is null, 
then use the ${:=} operator. 
cd ${HOME:=/tmp}
● We probably have a value set of HOME, so this will change to real home 
directory. If it wasn’t set, it would be set to /tmp, and we would be changing 
directory into /tmp. 
68
Giving an Error Message for Unset Parameters
● Use the ${:?} syntax when referring to the parameter. 
● Bash will print an error message and then exit if the parameter is unset or 
null.
MYPARAM=${1:?"Error. You must supply a parameter"}
● Here’s an output:
$ MYPARAM=${1:?"Error. You must supply a parameter"}
-bash: 1: Error. You must supply a parameter
